# CareerAct 产品设计原则

更新/来源阅读日期：2026-09-29。面向实现页面与评审交互的维护者和 Agent。
这是跨页面的设计约定；具体流程在[工作台交互规格](WORKSPACE_INTERACTION.md)，
已实现范围与交付顺序在 [STATUS](../engineering/STATUS.md)。不另建一套组件库或付费设计系统。

## 1. 参考依据与适用边界

以下官方正文已实际阅读。借鉴可观察的设计选择，将推导出的 CareerAct 约定与官方陈述分开；
不把“Less is more”当成未经证实的 OpenAI 团队原话，也不声称获得其内部设计规范。

| 官方来源 | 正文明确表达的内容 | CareerAct 的取舍 |
| --- | --- | --- |
| [OpenAI 品牌设计指南](https://openai.com/zh-Hans-CN/brand/) | 固定比例与一致性、清晰层级与留白；字体平衡技术精度、功能性与人文温暖 | 注重排版、比例、统一控件和友好文案，保留自己的渡鸦品牌 |
| [Canvas 简介，2024-10-03](https://openai.com/zh-Hans-CN/index/introducing-canvas/) | 聊天对反复修改的项目有限制；可直接编辑、选择局部、获取内联反馈、恢复版本 | 正文是工作对象；Agent 理解选区，修改可审阅，用户能接手与撤回 |
| [推出 Codex 应用，2026-02-02](https://openai.com/zh-Hans-CN/index/introducing-the-codex-app/) | 按项目组织工作、切换不丢上下文；查看修改与 Diff、手动编辑；自动化结果进入审核队列 | 按职业对象和任务组织内容；后台发现机会进入收件箱，待处理结果可以稍后继续 |

产品发布文章用于理解设计动机，不用于断言当前套餐、平台或全部功能。品牌指南不是完整
产品 UX 规范。完整品牌站点本次跳到认证入口，Apps SDK 设计文档返回 403，未将未读内容
列为依据。未下载品牌字体或标志，也不需要为本项目引入 OpenAI 的品牌资产。

## 2. 内容与任务优先

- 用户一进入应能判断：正在处理什么、当前是什么状态、下一步能做什么。
- 阅读/编辑材料时，正文占主要空间；查看机会时，优先看发生的变化、匹配原因与下一步。
  不用欢迎语、装饰性统计和大面积宣传区挤占工作内容。
- 一个主要工作区域围绕当前任务组织主要动作；来源、历史、筛选和高级选项按需展开。
  渐进呈现不能隐藏失败、尚未保存、待确认或外部动作的影响。
- Agent 入口始终可发现；打开文档或选择段落后直接携带上下文，不要求重复复制内容。
  不把整个应用做成聊天消息列表，也不把用户引导成一串填表步骤。
- 稳定的导航、焦点、选区与滚动位置比花哨的切换更重要。切换对象后不能残留上一对象的
  结果、错误或待接受修改；返回时能继续工作。

## 3. 视觉基础

下面是 CareerAct 的初始基线，具体尺寸由中文真实内容原型验证，不是 OpenAI 的参数。

| 方面 | 实现约定 |
| --- | --- |
| 字体与层级 | 复用现有字体方案并明确中文系统字体回退；正文以约 15–16px、1.5–1.7 行高试排；区分标题、正文、辅助信息，避免满屏小灰字或超大口号 |
| 间距与对齐 | 复用现有 spacing token，以 4/8px 步长组织常用间距；保持正文、工具栏、列表列线一致，不逐页随意微调 |
| 色彩 | 中性底色与高可读正文为主；强调色服务主要动作、选择和状态；“待核验”不能通过配色伪装成“已确认” |
| 容器与层次 | 优先通过留白、对齐和必要分隔线区分内容；卡片用于独立信息单元，弹层用适度阴影，不层层卡片套卡片 |
| 图标与圆角 | 复用当前图标库、语义 token 和组件尺寸；重要动作有文字，纯图标控件提供可访问名称与提示 |
| 动效 | 只解释状态变化、位置或进度；遵循减少动态效果偏好，不用持续闪烁、打字动画或装饰光效阻碍阅读 |
| 信息密度 | 档案/材料以阅读为主，机会列表以快速比较为主；不为追求留白而让一屏只能看到一条机会 |

不把渐变、阴影或颜色本身视为错误；没有内容或状态作用的装饰应删除。工作台不默认使用
营销页式巨型标题、霓虹光晕、每条内容一个彩色卡片或到处出现的“AI”徽章。
不强制先重做全部设计 token，也不因为参考产品而更换 shadcn/ui、编辑器或应用架构。

## 4. 简洁必须保留的反馈

- 自动保存显示真实结果：保存中、已保存、失败；流结束不等于任务完成，失败时保留输入。
- 长任务有简短业务进度、取消或待处理入口，恢复后显示实际任务状态，不展示内部推理链。
- Agent 修改就地审阅；理由与证据按需展开，接受范围明确，不增加重复确认。
- 机会结果默认回答“什么变化、为什么与你有关、何时核验、有什么未知、下一步是什么”。
  来源证据与匹配解释可以展开；监测失败与确实没有新机会不能共用空态。
- 只对值得及时处理的变化突出提醒，普通结果汇总。用户可以忽略、稍后处理或调整关注条件，
  不用通知数量制造焦虑；同一事件转载不反复弹出。
- 中文文案直接描述对象、动作和结果，如“查看来源”“接受这处修改”“暂未核实截止日期”。
  不用“智能赋能”“开启旅程”等泛化宣传语代替操作说明，也不夸大完成度。

## 5. 交付前如何检查

1. 用有长标题、中文段落、多条经历和多来源信息的虚构样本验收，不能只看空白页和短占位文案。
2. 在真实页面操作主要路径，验证 hover/focus、滚动、选区、键盘和对象切换；截图只验证静态
   排版，不替代交互验收。错误、冲突、空态、保存中与待确认态都须有明确出路。
3. 正常文字对比度至少 4.5:1，大字至少 3:1；焦点可见，Diff 与状态不只靠颜色区分。
   简洁不能以取消标签、压小字号或让按钮难以点击为代价。
4. 宽屏与约 390px 窄屏验证布局和长内容，不截断关键状态，不让三栏挤在一起；窄屏模拟
   与真机验收分开记录。
5. 先评审结构和任务路径，再打磨排版、间距、状态与动效。逐项说明问题和调整，不只用
   “像不像 OpenAI”“看起来高级”作为完成标准。

新增页面先复用这些约定；跨页面反复出现的新问题才更新本文。单次组件行为留在交互规格
或实现附近，不为每次界面改动追加设计报告或 Skill。
