## 问题与依据

现有页面验证了档案保存和用户隔离，但以表单为主，未能表达长期职业项目与 Agent
协同推进工作的关系。先前的档案/材料局部规格不足以定义整个工作台，需要先可视化验证。

产品围绕职业项目、背景、材料、任务、机会和成果组织；用户可表达意图，Agent 使用上下文
推进工作，结果可继续编辑和复用。不能用菜单数量或聊天消息数量代替这条工作路径。

本地有 `docs/PRD.md` 时阅读 1.3、3.3、3.8、4、5 节；技术边界遵循 `docs/ARCHITECTURE.md`。
公开入口为 [AGENTS](../../../AGENTS.md)、[当前实现](../../handbook/STATUS.md)和
[设计原则](../../handbook/DESIGN_PRINCIPLES.md)。PRD 的范围不由本专题修改。

## 本次范围

- 逐项映射 PRD 全部核心能力，保留菜单/入口和代表性交互，不因后端暂缓而省略产品范围。
- 结合真实使用，补齐申请查找与追踪、状态来源、沟通、日程、准备、决策和经历沉淀的关系。
- 让用户在浏览器体验表达意图、选择上下文、审阅和编辑成果、继续推进，以及等待和失败。
- 先验证整体组织和主要交互，再打磨中文排版、密度、留白、控件与窄屏切换。

本次交付可见原型及确认结论。真实 API、数据库迁移、Agent 工具、外部投递与完整功能模块
不在本次交付中；接入顺序由原型验收结果决定，不提前写成已批准的实现方案。

## 验收条件

- 用户能判断当前职业项目、正在处理的内容、Agent 的任务及可继续的动作。
- 用户可以从意图或已有内容开始，不要求先填写完整档案；成果能回到相关职业内容。
- 使用现有原型在可见浏览器操作代表性路径，确认主要交互；截图不作为每次迭代的必交产物。
- 模拟行为与实际已实现能力可区分；能检查长中文内容、内容切换和窄屏下的可用性。
- 记录用户实际确认的形态、未解决问题及后续真实功能的最小目标，不以静态截图代替功能验收。

研究结论已确认：“Agent 主创的共创工作室＋常驻职业伙伴”，职业路线作为项目视图；首屏、角色与协作边界冻结为正式实现基线。

第一版代表路径：项目首页 → 材料审阅 → 一次申请的授权与结果 → 面试准备；另含机会调研、
职业背景、工程作品项目与空态。它用于检验职业项目承载能力，不代表所有能力已经实现。
原型保留 22 个可导航视图；首页另可切换三种候选形态。视图数不是完成度，深度与接口落点只在 DESIGN 维护。

公开产物使用虚构但有真实复杂度的内容。本地 Dogfood 可使用用户选定的真实资料，
保留在忽略范围；不全量导入 career，不因原型测试自动向模型发送资料。

### 当前评审结论

当前版本完成形态讨论，不是正式业务实现。已确认保留完整功能与来源关系，首屏采用 Agent 主创的共同工作面，并以常驻伙伴承载持续职责；
三种方案及推荐理由见 [形态研究与候选方案](DESIGN.md#第二轮形态研究与候选方案)。
覆盖复核发现第一版在申请追踪、招聘沟通、日程、Offer 决策、成长、后台任务和托管设置上
缺少独立入口或代表 UI，已补入现有原型；PRD 和正式应用源码未改。

输入可保留委托并选择工作去向。共创工作室的项目经历段落与全文审阅使用同一页面草稿；
用户可反馈、精确修正后交还、接受或拒绝固定补充，旧提议不能覆盖新正文。其他材料的版本恢复仍为独立场景；多数页面固定了
样例对象，任意项目/岗位的动态关联、长期保存与真实 Agent 调用尚未接入。

正式前端基座的代码已落实为 Next.js App Router 页面、真实导航、项目工作面、Agent 侧区和统一空态边界；当前只待 Docker 启动后的可见验收。除已存在的职业档案 API 外没有伪造领域数据。基座验收后，再实现材料 Agent 主创、用户审阅/反馈、版本保存与刷新恢复；该路径先不接真实招聘网站写操作、自动投递或无人值守托管。
不能把入口补齐当作产品体验已合格，也不将本轮视觉细节当成已确认规格。

6901 是上一轮临时首屏草图，没有完整功能，已停止维护；当前可见评审统一使用 3210。
本轮没有新增并行完整 UI；没有修改 `apps/`、`services/`、PRD 或 ARCHITECTURE。
